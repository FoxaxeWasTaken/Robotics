### Fixed

- Kinematics (#145, `04` §8, MES-43): no IK solution folds the arm onto itself any more. ikpy knows no collision volumes; from the startup pose it folded the elbow to 1.69 rad for a target of `test_ik_accuracy`, the lower arm on the shoulder, and the arm stopped 28.4 mm short. `Kinematics.self_collides` (the elbow past 1.50 rad, or the lower arm, wrist or gripper inside a 10 cm cylinder around the pan axis below 12.5 cm) is checked in `_solve`, the path of `ik_pos`, `ik_point` and `ik_pose`, and the next seed is tried. Against MuJoCo on 30,000 random poses: 0 of 3,788 self-contacts missed, 9.6 % of the free poses rejected too; `PARK` stays clear.
- Brain (#143): a cube already in the box is no longer grasped. A `/brain/start` without `/sim/randomize` after a cycle locked it and closed the jaws on the cube and the box wall together (effort 1.000, then `ERROR:timeout:LIFT`). The lock now applies `VERIFY`'s footprint test (`fsm.box_half_size_m`, written once): such a cube goes from `WAIT_TARGET` to `DONE` "cube already in the box", with no motion after `PARK`.
- Control container stop (`docker compose stop`/`down`, step 6.1a): the nodes never got a SIGINT, so `destroy_node()` never ran (no "Robot disconnected", exit 137 after about 3.5 s). Compose gives `control` a TTY, and an interactive `ros2 launch` takes a SIGINT for a terminal Ctrl-C its nodes got too and does not forward it; the entrypoint now starts it with `--noninteractive`, and `stop_grace_period: 10s` lets the driver park the arm. Measured: stop in 4.6 s, `Shutdown pose reached in 3.8 s`, exit 0.
- `test_ik_accuracy` at random (#142): once in CI, the arm stayed 13.9 mm above target 15. Each target was seeded with the joints the previous one left, so the position IK found other solutions from run to run, and some fold the elbow to its limit, where the lower arm hits the shoulder in MuJoCo [MES-43]. Each target now starts from HOME (0, −1.0, 0.7, 0, 0): the same 20 solutions in every run, none colliding (3/3 runs: max 0.218 mm). The start pose q = 0 was no fix: straight, it is singular, and target 4 then failed in every run (28.4 mm). The obstacles are read after `/sim/randomize` replied (read after the call, they were the old ones in 2 runs of 6), and a miss prints how far each joint stayed from the command. The C-41 threshold is unchanged, and a 2 cm IK mutant still fails it.
- The E2E bench at a stack start (#141): once, on a CI runner, `evaluate` stopped before its first episode with `/so101_driver/get_parameters: no such service`; its rerun did 3/3. On a stack pinned to 2 cores, a fresh process finds the driver in 1.5 to 1.8 s (5 runs), so the cause is not the load alone. On `main` (ce96187), it then stopped on no `/end_effector_pose` within 10 s. Then, once, the driver was found but its reply never came in 60 s. The checks before the first episode (driver, ground truth, brain pose) now wait up to 60 s each; the first one, which changes nothing, is sent again every 5 s without a reply, and prints how long it took and which request got the reply; both E2E jobs print `docker compose ps -a` and the stack logs on failure. With that, 2 of 5 E2E runs still lost a node for 60 s (no such service; no brain pose), never the control tests, which run without `LARGE_DATA`. Locally, under `LARGE_DATA` the driver's first reply took 1.4 to 5.8 s (once only the resend got it), under `DEFAULT` 0.5 to 0.8 s. Both E2E jobs now run the stack on the `DEFAULT` Fast DDS transports (`docker-compose.yml` keeps `LARGE_DATA` by default) and, on failure, show which nodes and topics a fresh process still reaches.
- A cycle started before the brain sees `/joint_states` (#132): `test_pick_place_gt_launch` failed once in CI with `ERROR:no_joint_states`, `/brain/start` 13 ms after "Brain node ready". It and `test_ik_accuracy` now wait for the first `/end_effector_pose`, as `test_brain_launch` does (#119); `evaluate` too, and stops (exit 2) without one in 10 s.
- Sim `camera_info`: the principal point is now in OpenCV pixel coordinates, (159.5, 119.5) at 320×240 instead of the provided (160, 120), which put pixel edges on integers. Every OpenCV centroid was half a pixel off: cube error 2.63 → 0.50 mm mean over 50 scenes (MES-41, #122), 2.39 → 0.78 mm on the reference images. The reference images' `labels.json` carries the same K; the images are unchanged.
- Driver and brain: timers and motion time on the steady clock. On WSL2 the system clock steps back ~2.6 s every 30 s: `/joint_states` stopped and motions froze for 2.6 s at each step; largest `/joint_states` gap now 37 ms [MES-37].

- Driver: SIGINT or SIGTERM while a timer callback publishes no longer ends in a traceback and exit code 1 (seen once in 40 SIGTERM stops).
